# Emotional Diary Service

Сервис, который помогает трейдеру бороться с эмоциями: обязательный допуск к сессии,
автоматические детекторы нарушений, блокировки с разбором и внешний контроль
через доверенное лицо.

Документы проекта (ТЗ, дизайн, архитектура, план разработки) лежат в Obsidian:
`Documents/Brain/Projects/Emotional Diary Service`.

## Стек

Python 3.12 + FastAPI · PostgreSQL 16 · SQLAlchemy 2 (async) · Alembic ·
модульный монолит со швами на разрез · события через outbox в базе.

## Запуск

Нужен только Docker Desktop.

```
copy .env.example .env      # Windows; на unix: cp .env.example .env
docker compose up --build
```

Дальше:

- <http://localhost:5173> — интерфейс (вход, настройки)
- <http://localhost:8000> — страница состояния сервиса
- <http://localhost:8000/docs> — документация API

Остановить: `Ctrl+C`, затем `docker compose down`.
Стереть базу и начать с нуля: `docker compose down -v`.

## Что уже работает

**Шаг 0 — каркас.** Страница состояния показывает версию, соединение с базой,
номер применённой миграции, девять схем модулей и состояние событийной шины.
Кнопка «Отправить тестовое событие» публикует событие в `events.outbox`;
консьюмер забирает его и сдвигает курсор — это видно на той же странице.

**Шаг 2 — источник и лента сделок.** Порт `TradeSource` и фейковый источник:
сделки подаются в него кнопкой и забираются обычной сверкой — тем же путём,
которым пойдут настоящие. Приём считает торговый день по времени открытия
и таймзоне трейдера, значимость по порогу, разметку по тегам; повторная сверка
ничего не дублирует. Лента сделок с фильтрами и итогами по всей выборке,
кривая дня, словарь тегов с отметкой «это нарушение» — её изменение
переразмечает принятые сделки через событийную шину.

**Шаг 1 — вход и настройки.** Регистрация и вход по куки-сессии (`HttpOnly`
плюс CSRF-токен двойной отправкой), модуль `identity`, экран настроек:
таймзона, граница торгового дня, пороги чека, порог значимости, режим наблюдения.
Список активных входов с возможностью оборвать любой. Фронт — React 18 + TypeScript
+ Vite + TanStack Query, тёмная тема из прототипа.

План следующих шагов — в документе «План разработки».

## Тесты

Без базы (границы модулей, контракты, форма health):

```
docker compose run --rm api pytest -q
```

С базой (шина, схемы):

```
docker compose run --rm -e TEST_DATABASE_URL=postgresql+asyncpg://eds:eds_local_password@db:5432/eds api pytest -q
```

## Структура

```
src/eds/
├── contracts/     события и порты — единственное, что импортируют все
├── app/           оркестрация: единственное место, знающее несколько модулей
├── platform/      конфиг, база, шина, логи, аутентификация
├── modules/       модули: у каждого свой пакет и своя схема в базе
├── entrypoints/   процессы: api (дальше — stream, worker, bot)
└── web/           страница состояния сервиса
web/               SPA: React + TypeScript + Vite
alembic/           миграции, одна история на все схемы
tests/             включая проверку границ между модулями
```

## Правила, о которых легко забыть

- `.env` в репозиторий не попадает. Ключи TMM и Binance живут только там.
- Модуль не импортирует другой модуль. Это проверяет `tests/test_boundaries.py`.
- Откат миграций не поддерживается: назад — только восстановлением дампа.
- Все расчёты на сервере. Фронт ничего не считает сам.
